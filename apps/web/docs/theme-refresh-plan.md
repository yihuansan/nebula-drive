# NebulaDrive 三主题大更新 · 项目计划
**范围**：系统设置 → 外观 中的 **仪表盘(dashboard) / 便当盒(bento) / 命令式(command)** 三个主题
**目标**：焕然一新（视觉 + 交互 + 代码质量三重达标）
**技术栈**：Vue 3 + Element Plus + Vite（前端）· Fastify（后端，本项目不涉及）
**约束**：范围严格限定在这三个主题，**不得**波及其他 6 个主题（light-glass / dark-glass / top-nav / stardust / dawn / flow）

## 一、现状分析

### 1.1 主题元数据（`apps/web/src/useTheme.ts`）
| key | label | icon | isGlass | layout |
|---|---|---|---|---|
| `dashboard` | 仪表盘 | 📊 | true | `dashboard` |
| `bento` | 便当盒 | ▦ | true | `bento` |
| `command` | 命令式 | ⌘ | false | `command` |

布局渲染链路：`useTheme().theme` → `layoutType = THEMES[theme].layout`（`App.vue` L15 / `Files.vue` L77）→ 主视图 `Files.vue` 按 `layoutType` 挂 `.files-dashboard / .files-bento / .files-command` 类，并在 `v-if="layoutType==='dashboard'"` 时渲染统计卡。

### 1.2 仪表盘 dashboard
**CSS 变量段**（`glass.css` L102-116，**仅一段变量，无任何组件级覆盖**）：
- `--bg: linear-gradient(135deg,#667eea,#764ba2)`（经典紫渐变）
- `--blur:20px` · `--glass-bg:rgba(255,255,255,.25)` · `--accent:#fbbf24`（琥珀）· `--text:#fff`
**视图层**（`Files.vue`）：
- `.stats-bar`（L2002）：3 张统计卡（文件夹 / 文件 / 总大小），`statCards` 计算属性（L83）
- 图标渐变 `si-blue/si-green/si-purple`（L2025-2027）

**问题**：
1. 2014 年模板感紫渐变，无产品辨识度。
2. 白字压在 25% 白玻璃上，对比度差、数值发灰。
3. 统计卡静态、仅 3 张、无趋势/动画。
4. **无组件覆盖**（按钮/对话框/输入框全继承基础玻璃样式，与白字冲突）。

### 1.3 便当盒 bento
**CSS 变量段**（`glass.css` L119-136）：
- `--bg:#f0f4f8`（纯平灰）· `--blur:0` · `--glass-bg:rgba(255,255,255,.9)` · `--accent:#10b981`（绿）· `--text:#1e293b`
- 仅 `border-radius:16px` 覆盖
**视图层**（`Files.vue` L2769-2785）：
- `.files-bento .file-grid`：`auto-fill minmax(180px,1fr)`
- `nth-child(5n+1)` 跨 2 列、`nth-child(7n+3)` 跨 2 行；`border-radius:20px`

**问题**：
1. 纯平灰背景，无层次、无景深。
2. 卡片全白同质，**无 featured 主卡、无彩色块**，不像"便当盒"（便当盒应有不同格子的色彩与尺寸节奏）。
3. 尺寸变化仅靠 `nth-child` 随机跨度，无视觉层级。

### 1.4 命令式 command
**CSS 变量段**（`glass.css` L141-170）：
- `--bg:#000000`（纯黑）· `--blur:0` · `--glass-bg:rgba(30,30,30,.95)` · `--accent:#ff6b35`（橙）
- `body` 全局等宽字体（L156）· `border-radius:6px` · 对话框/输入框覆盖
**视图层**（`Files.vue` L2787-2837）：
- `.files-command .toolbar { display:none }`（**真实搜索框被隐藏**）
- `file-grid` 变竖排列表；`file-card` 变横排行
- `.files-command::before { content:'⌘ 搜索文件...' }`（**静态伪元素，假的**）

**问题（最严重）**：
1. **"命令面板"是假的**——`::before` 只是静态文字，真实搜索框被 `display:none`，没有 ⌘K、没有模糊搜索、没有键盘导航。
2. 纯黑 `#000` 生硬刺眼。
3. 等宽字体全局套用，长内容可读性差。

### 1.5 横向对比结论
较新的 stardust/dawn/flow（`glass.css` L595-1042）已具备完整 `.layout/.aside/.header/.file-grid/.file-card/.menu-item` 覆盖 + flow 的 `.ai-panel`；而三个目标主题停留在"变量段 + 少量覆盖"。**三个主题是当前主题体系里的"落后梯队"，需整体重做，而非换色。**

## 二、"焕然一新"目标定义（具体、可验收）

> 统一验收基线（三主题共用）：
> - **对比度**：正文/数值文字对背景满足 WCAG AA（正文 ≥4.5:1，大字号 ≥3:1）。
> - **组件一致**：`el-button / el-dialog / el-input / el-select / el-tag / el-message` 在该主题下风格统一、无刺眼默认色。
> - **移动端**：≤768px 布局可用（统计卡换行、网格降列、命令面板全宽）。
> - **隔离**：所有改动仅命中 `[data-theme='dashboard|bento|command']` 与 `.files-*` 作用域，其他 6 主题截图无变化。

### 2.1 仪表盘 dashboard —— "现代控制中心"
- [ ] 背景：替换 2014 紫渐变为有辨识度的现代背景（分层/微动效渐变或深色科技底），不再是模板紫。
- [ ] 文字：修正白字发灰，主数值高对比、标签次级色清晰。
- [ ] 统计卡：≥4 张（新增"存储用量"或"最近活动"），带趋势指示（↑↓/百分比）与入场动画。
- [ ] 组件：按钮/对话框/输入框按本主题重设（Element Plus 覆盖）。
- [ ] 主色：保留或重设 accent，按钮实心态可读。
- **验收点**：截图对比旧版一眼可辨"换了产品"；统计卡入场动画可见；对话框/按钮风格统一。

### 2.2 便当盒 bento —— "真正的便当盒"
- [ ] 背景：纯平灰 → 柔和分层底（微渐变/纹理），有景深。
- [ ] 网格：建立**真实层级**——1 张 featured 主卡（大）+ 中卡 + 小卡，尺寸节奏明确（非随机 nth-child）。
- [ ] 彩色块：≥2-3 张 accent/彩色 tile，打破全白同质。
- [ ] featured 卡：承载**真实数据**（如存储用量环 / 高亮文件 / 最近项）。
- [ ] 主色：green 精调或换新色板。
- **验收点**：网格一眼看出"主卡 + 不同尺寸 + 彩色格"，不再是均质白网格；featured 卡显示真实数据。

### 2.3 命令式 command —— "真·命令面板"
- [ ] **真命令面板**：`⌘K / Ctrl+K` 打开；模糊搜索过滤文件；方向键↑↓ + Enter 选中；结果列表带图标。
- [ ] 搜索优先：命令面板成为主入口（不再是隐藏工具栏 + 假 `::before`）。
- [ ] 暗色精修：纯黑 `#000` → 深炭/深海军蓝，有层次。
- [ ] 等宽字体：仅用于命令/结果区，不再全局套用。
- [ ] 列表：文件列表呈现为"命令输出/结果"质感。
- **验收点**：`⌘K` 真能打开面板；输入即时过滤；键盘可导航并选中；暗色不再纯黑刺眼。

## 三、任务拆解

> 隔离原则（贯穿所有任务）：一切改动用 `[data-theme='...']` + `.files-*` 作用域；**不改**共享基础样式（`.file-grid/.file-card/.stats-bar` 的通用定义）与全局 Element Plus 覆盖，避免波及其他 6 主题。

### T1 · 三主题设计契约 + CSS 系统规范
- **做什么**：产出三主题的视觉设计契约（设计系统 + 可落地 CSS 规范），作为后续实现与验收的唯一依据。
  - 每主题：视觉身份（背景/色板/字体/圆角/阴影）、布局结构（仪表盘=统计卡网格、便当盒=层级网格、命令=命令面板）、Element Plus 组件覆盖规则、动效规范。
  - 共享：CSS 变量命名、`[data-theme]` 覆盖结构、隔离边界声明。
- **改哪些文件**：新建 `apps/web/docs/theme-refresh/design-contract.md`（交付物）；**不**改代码。
- **验收标准**：契约覆盖三主题全部视觉要素 + 组件覆盖规则 + 隔离边界；每条"焕然一新"目标（第二章）都有对应可验收的规范条目；评审（UI 设计师 + 验收设计师）签字确认。

### T2 · 仪表盘 dashboard 视觉实现
- **做什么**：按契约重设 dashboard——新背景/色板、统计卡升级为 ≥4 张 + 趋势 + 入场动画、Element Plus 组件覆盖。
- **改哪些文件**：
  - `glass.css`：`[data-theme='dashboard']` 变量段（L102-116）重写 + 新增本主题组件覆盖块（`.el-button/.el-dialog/.el-input__wrapper/.el-tag` 等）。
  - `Files.vue`：`statCards`（L83）新增卡片；`.stats-bar/.stat-card`（L2002-2036）按契约调整；`.files-dashboard` 布局类样式。
  - `useTheme.ts`：dashboard 元数据（icon/label）按需微调。
- **验收标准**：对照 T1 契约逐项达标；统计卡 ≥4 张、有趋势与入场动画；白字发灰消除；组件风格统一；其他 6 主题无变化。

### T3 · 便当盒 bento 视觉实现
- **做什么**：按契约重设 bento——分层背景、真实层级网格（featured 主卡 + 中/小卡）、彩色 tile、featured 卡承载真实数据。
- **改哪些文件**：
  - `glass.css`：`[data-theme='bento']` 变量段（L119-136）重写 + 新增组件覆盖块。
  - `Files.vue`：`.files-bento`（L2769-2785）重构网格层级；新增 featured 卡模板与样式；彩色 tile 类。
  - `useTheme.ts`：bento 元数据按需微调。
- **验收标准**：网格有明确主卡 + 尺寸节奏 + ≥2-3 彩色 tile；featured 卡显示真实数据；纯平灰消失；其他 6 主题无变化。

### T4a · 命令式 command 视觉层
- **做什么**：按契约重设 command 视觉——深炭/深海军蓝暗色（非纯黑）、等宽字体限定作用域、列表"命令输出"质感、组件覆盖。
- **改哪些文件**：
  - `glass.css`：`[data-theme='command']` 变量段（L141-170）重写；`body` 等宽字体（L156）改为限定作用域；组件覆盖块精修。
  - `Files.vue`：`.files-command`（L2787-2837）列表质感重设；移除假的 `::before`（L2829-2837）。
- **验收标准**：暗色不再纯黑刺眼；等宽字体不再全局；列表有命令质感；假 `::before` 已移除；其他 6 主题无变化。

### T4b · 命令式 command 命令面板交互（核心）
- **做什么**：实现**真命令面板**——`⌘K/Ctrl+K` 打开、模糊搜索过滤、↑↓+Enter 键盘导航、结果列表带图标；面板成为主入口。
- **改哪些文件**：
  - `Files.vue`：新增响应式状态（`cmdOpen/cmdQuery/cmdResults/cmdIndex`）、键盘监听（`onMounted/onUnmounted`）、模糊匹配函数；新增命令面板模板 + 样式；仅在 `layoutType==='command'` 时激活。
  - `glass.css`：`[data-theme='command']` 下命令面板专用样式。
- **验收标准**：`⌘K` 真能打开；输入即时过滤（模糊）；↑↓ 移动高亮、Enter 选中并跳转/打开；Esc 关闭；非 command 主题不激活；键盘可达（a11y）。

### T5 · 三主题点睛互动细节
- **做什么**：在三主题上叠加"让人记住"的互动细节——微交互、过渡、惊喜时刻（如统计卡数字滚动、bento 卡片 hover 抬升、command 面板滑入/光标闪烁）。
- **改哪些文件**：`Files.vue`（三主题布局类的动效/微交互）+ `glass.css`（`[data-theme]` 动效变量/keyframes）。
- **验收标准**：每主题 ≥1 个可感知的"惊喜"细节；动效克制（不喧宾夺主、不伤性能）；与 T1 动效规范一致。

### T6 · 三主题视觉验收
- **做什么**：对照 T1 设计契约**逐项**验收三主题；拦截"雷同界面"（三主题必须各自有独立身份，不得互相抄袭/趋同）；输出**整改清单**。
- **改哪些文件**：不直接改代码；产出 `apps/web/docs/theme-refresh/acceptance-report.md`（含每主题截图 + 逐项结论 + 整改清单）。
- **验收标准**：每主题截图（桌面 + 移动端）齐全；对照契约逐项打勾/打叉；三主题彼此可区分；问题清单明确到"哪个文件哪个点"。

### T7 · 代码审查
- **做什么**：审查本次改动的正确性 / 可维护性 / 安全性——CSS 作用域隔离是否守住（不波及其他 6 主题）、命令面板 JS（事件监听清理、内存泄漏、XSS/注入、键盘处理边界）、Vue 响应式正确性。
- **改哪些文件**：不直接改代码；产出 `apps/web/docs/theme-refresh/code-review-report.md`（问题分级：Blocker/Major/Minor）。
- **验收标准**：确认隔离边界未被破坏；命令面板无泄漏/无未清理监听；无安全回归；问题清单分级明确。

### T8 · 整改闭环（条件任务）
- **做什么**：依据 T6 整改清单 + T7 问题清单，回改代码直至达标。
- **改哪些文件**：T6/T7 指出的文件（通常是 `glass.css` + `Files.vue`）。
- **验收标准**：T6 复验通过（契约逐项达标 + 三主题可区分）且 T7 无 Blocker/Major 残留。

## 四、专家分工

| 任务 | 专家 | 理由 |
|---|---|---|
| T1 设计契约 + CSS 规范 | **design-ux-architect** | UX 架构师职责=梳理信息架构与交互流程、**制定 CSS 系统规范**、输出可落地实现指引——契约是后续实现与验收的唯一依据，必须由架构师定。 |
| T2 dashboard 实现 | **design-ui-designer** | UI 设计师是"设计+实现"主力，能落地实现；dashboard 以视觉重设 + 统计卡为主，是其核心能力。 |
| T3 bento 实现 | **design-ui-designer** | 同上；bento 网格层级 + 彩色 tile 属视觉系统搭建，UI 设计师交付高保真并可落地。 |
| T4a command 视觉层 | **design-ui-designer** | 暗色精修 + 列表质感属视觉系统，UI 设计师负责。 |
| T4b command 命令面板交互 | **design-ui-designer** | 命令面板是"交互 + 实现"结合，UI 设计师能落地实现（含 JS）；这是本主题核心。 |
| T5 点睛互动细节 | **design-whimsy-injector** | 创意设计师职责=加趣味/惊喜、设计**让人记住的互动细节**——点睛之笔由其负责，避免 UI 设计师把"惊喜"做成"常规"。 |
| T6 视觉验收 | **design-ui-finish-gate-reviewer** | 视觉验收设计师职责=**对照设计契约逐项验收**、**拦截雷同界面**、输出整改清单——天然匹配。 |
| T7 代码审查 | **engineering-code-reviewer** | 代码审查工程师职责=审查**正确性/可维护性/安全性**——命令面板 JS 与 CSS 隔离边界由其把关。 |
| T8 整改闭环 | **design-ui-designer** | 回改代码回到实现主力；按验收/审查清单执行。 |

**分工原则**：UX 架构师出规范（定标准）→ UI 设计师做设计+实现（落地）→ 创意设计师加点睛（惊喜）→ 视觉验收设计师做验收（拦截）→ 代码审查工程师做代码审查（质量）。

## 五、执行顺序

```
T1 (UX 架构师 · 设计契约)            ── 串行，地基，必须最先
        │
        ├──────────────────────────────┐
        ▼                              ▼
T2 (dashboard)  ∥  T3 (bento)  ∥  T4a (command 视觉)   ── 并行（各自 [data-theme] 段 + .files-* 段，互不冲突）
        │                              │
        └──────────────┬───────────────┘
                       ▼
              T4b (command 命令面板)   ── 依赖 T4a（面板需先有视觉层）
                       │
                       ▼
              T5 (创意设计师 · 点睛)   ── 依赖 T2/T3/T4（在核心实现上叠加）
                       │
                       ▼
              ┌────────┴────────┐
              ▼                 ▼
     T6 (视觉验收)      T7 (代码审查)   ── 并行（两个不同视角）
              │                 │
              └────────┬────────┘
                       ▼
              T8 (整改闭环)   ── 条件任务：仅当 T6/T7 有问题时触发
                       │
                       ▼
              复验 T6 + T7  →  通过 → 汇报
```

**关键依赖**：
- **T1 必须最先**（契约是实现与验收的唯一依据）。
- **T2/T3/T4a 可并行**（分属不同 `[data-theme]` 段与 `.files-*` 段，文件级不冲突）。
- **T4b 依赖 T4a**（命令面板需要视觉层先就位）。
- **T5 依赖 T2/T3/T4**（点睛在核心实现之上叠加）。
- **T6/T7 可并行**（视觉验收 vs 代码审查，不同视角）。
- **T8 是条件闭环**，触发后回到 T6/T7 复验。

**说明**：T2/T3/T4a 虽"可并行"，但同属 UI 设计师一个实现主体且共享 `glass.css`/`Files.vue` 两个文件，实际由 UI 设计师按"协调式一次实现"推进（按 T2→T3→T4a 顺序落笔，避免同文件互相覆盖）；并行性体现在**任务可独立验收**，而非三人同时编辑同一文件。

## 六、整体"通过"标准（功能 + 视觉 + 代码）

> 只有以下三类**同时**满足，才判定"焕然一新"通过、可汇报。

### 6.1 功能（功能验收）
- [ ] 三主题均可正常切换（`useTheme.setTheme`），`<html data-theme>` 正确切换、`localStorage` 持久化。
- [ ] **command**：`⌘K/Ctrl+K` 打开真命令面板；模糊搜索过滤；↑↓+Enter 导航选中；Esc 关闭；非 command 主题不激活。
- [ ] **dashboard**：统计卡 ≥4 张且数据真实（文件夹/文件/总大小/存储用量或最近活动）；趋势指示正确。
