# NebulaDrive 星云网盘 · 大改版后 UI 逐屏走查报告

> **走查性质声明**：本报告为**定性走查**（读取设计代码 + 设计蓝图 + 基于 CSS 推理渲染结果），非浏览器实测、非统计证据。所有视觉判断均来自代码推理，落地前建议设计师在真实浏览器中按本报告标注的位置复核一遍。结论是"强假设"，用于指导修改方向，而非已验证事实。
>
> **走查视角**：个人网盘用户（管理文件、看视频/图片、分享、收藏）。
> **评估范围**：登录 → Files → 预览 → Recent → Media → Favorites → QuickAccess → Recycle → HiddenSpace → Shares → Profile → 管理端，外加 3 个新主题（星尘 / 晨曦 / 流光）的重点评估。
> **约束**：本次只评估、不修改任何代码。

## 二、逐屏走查记录

> 每屏给出：情感反应（第一反应）/ 理性反应（注意到什么）/ 具体问题（可定位）。

### 1. 登录页 `Login.vue`

- **情感反应**：界面干净，品牌从 `/settings` 拉取，有验证码（可选）和 2FA（可选），注册开关。第一感觉"正规"。
- **理性反应**：只有"用户名 + 密码 + 可选验证码 + 可选 2FA"。没有"忘记密码"，没有"记住我"。
- **具体问题**：
  - **无忘记密码**：个人用户忘记密码 = 无法自助恢复，只能找管理员。对个人网盘这是硬伤（P1）。
  - **无记住我**：每次都要输账号，体验偏冷（P2）。
  - 验证码 `captchaCode` 明文存在客户端 ref（安全面，非 UX，顺带记录）。

### 2. 文件管理 `Files.vue`（核心主界面）

- **情感反应**：功能很全——网格/列表/照片三种视图、统计卡、标签、收藏星标、重命名/移动/复制、预览、上传、分享。第一眼"东西很多"。
- **理性反应**：
  - 工具栏 **13+ 个控件**密集排布（视图切换、多选模式、统计卡、标签、星标、搜索按钮等）。
  - 搜索是**藏在按钮后**的对话框（`Files.vue:1244` 触发，`:1605` 弹窗），带高级过滤（扩展名/大小/日期），能力不错但入口不显眼。
  - 卡片操作是**纯图标 + tooltip（hover 300ms 延迟）**，触屏无发现性。
  - 上传 ≤10MB 直传、否则分块（逻辑合理）。
- **具体问题**：
  - **工具栏信息过载**：个人用户高频动作只有"上传 / 新建 / 查找 / 分享"，其余被压平到同一行，扫描成本高（P1）。
  - **卡片操作可发现性差**：纯图标 + 延迟 tooltip，新用户不知道能干什么；触屏设备完全不可达（P1）。
  - 搜索入口弱：全局搜索是网盘核心能力之一，却藏在按钮里（P2）。

### 3. 文件预览（Files 内预览 + 图片画廊）

- **情感反应**：图片/PDF/代码/视频/音频都能预览，图片还有画廊导航/缩放/工具栏，体验不错。
- **理性反应**：预览能力齐全，是产品亮点。
- **具体问题**：视频预览的实际实现问题见 Media 屏（同一套 blob 下载逻辑）。

### 4. 最近全部 `Recent.vue`

- **情感反应**：有存储选择 + 过滤徽章（全部/文件/文件夹）+ 清空，卡片式，预览弹窗（缩放/旋转/适配）。
- **理性反应**：
  - `.stat-badge` 背景**硬编码白色** `rgba(255,255,255,0.5)`（`Recent.vue:427`），在暗色主题（深色玻璃/星尘/流光）下明显违和。
  - 卡片操作箭头 **hover 才出现**（`opacity:0`，`:465`/`:523`），触屏无发现性。
  - `limit=100`，无分页、无搜索。
- **具体问题**：暗色主题下白色徽章刺眼（P2）；卡片操作触屏不可达（P2）；无分页/搜索（P2）。

### 5. 视频文档 `Media.vue`

- **情感反应**：视频/文档双 tab，点进去想在线看视频。
- **理性反应**：
  - **视频预览用 `res.blob()` 把整个文件下载到内存后才播放**（`Media.vue:78-83`）——无流式、无 seek、大视频内存爆炸、体验极差。
  - **无视频缩略图**：列表只有 42px 图标，看不出是哪个视频。
  - 代码预览用 `document.querySelector('.preview-code code')` 直写 DOM（脆弱，非 UX）。
  - 空状态单行"暂无视频文件"，无引导。
- **具体问题**：视频预览整文件 blob 下载是"看视频"这一核心场景的硬伤（P0 级）；无缩略图（P1）；空状态无引导（P2）。

### 6. 收藏 `Favorites.vue`

- **情感反应**：骨架屏（150ms 延迟）有加载反馈，星标即时反馈，失效收藏（文件已删）标 `valid:false` 可移除，预览/移动/删除/分享齐全。
- **理性反应**：整体完成度不错，是相对健康的页面。
- **具体问题**：无搜索/过滤/文件夹分组——收藏多了难找（P2）。

### 7. 快捷访问 `QuickAccess.vue`

- **情感反应**：极简网格 + 星标 toggle。
- **理性反应**：**空状态提示"在文件管理中点击星标图标即可添加"（`QuickAccess.vue:76`）是误导**——Files 里的星标是"收藏"（走 `/favorites`），不是"快捷访问"（走 `/files/quick-access`）。用户照做会发现根本加不进去 → 死胡同。
- **具体问题**：空状态引导错误 + 快捷访问无真实添加路径说明（P1）。

### 8. 回收站 `Recycle.vue`

- **情感反应**：KPI 卡（项数/大小/自动清理周期，保留天数来自 settings）+ 表格多选 + 批量恢复/彻底删除。
- **理性反应**：结构清晰，KPI 有用。
- **具体问题**："本地副本"列对个人用户概念模糊（不知道指什么、有什么用）（P2）。

### 9. 隐藏空间 `HiddenSpace.vue`

- **情感反应**：设密码 → 解锁 → 文件网格，流程清楚。
- **理性反应**：
  - **无上传入口**：解锁后只有文件网格，没有上传/移动操作。
  - 空状态称"把文件移到 /hidden 目录"，但本页无上传/移动操作 → 死胡同。
  - **无重新锁定按钮**：解锁后一直解锁，没有"锁定"动作。
  - 密码明文 JSON 传输（安全面，顺带记录）。
- **具体问题**：无上传入口 + 空状态误导 + 无重锁（P1）。

### 10. 我的分享 `Shares.vue`

- **情感反应**：KPI（总数/有效/已过期）+ 搜索过滤 + 表格；创建对话框（存储/路径/名称/密码/有效期/下载次数，预填系统默认有效期）；复制链接/打开预览/删除；状态机（已过期/即将过期/有效/永久）。
- **理性反应**：完成度高，状态机清晰，是相对健康的页面。
- **具体问题**：无明显 UX 硬伤。

### 11. 我的资料 `Profile.vue`

- **情感反应**：头像/邮箱/bio/手机；存储用量条；登录历史；搜索历史；2FA（QR+恢复码）；设备会话管理（删除当前/其他/全部）。
- **理性反应**：安全面完整——**有"修改账号和密码"区块**（原密码/新密码≥8位/确认）、2FA、设备管理。
- **具体问题**：**无主题切换**（与全局"个人用户无主题入口"一致，P0 的一部分）。

### 12. 转存和订阅 `Subscriptions.vue`

- **情感反应**："转存和订阅"tab。
- **理性反应**：
  - **`doTransfer()` 用 `window.prompt('请输入分享链接：')` 原生弹窗输入**（`Subscriptions.vue:33`）——核心功能（转存分享）用浏览器原生 prompt，无校验/预览/进度，体验粗糙。
  - 订阅卡片**无操作**（无删除/打开/详情）。
  - 空状态"暂无订阅"无引导。
- **具体问题**：转存用 window.prompt（P1）；订阅卡片无操作（P2）；空状态无引导（P2）。

### 13. 公开分享 `PublicShare.vue`（`/s/:token`）

- **情感反应**：密码提取 → ticket → 目录浏览（面包屑）/文件卡片；锚点流式下载；转存对话框（未登录提示先登录，可选文件+目标路径）。
- **理性反应**：流程完整，ticket 机制清晰，分享方体验 OK。
- **具体问题**：无明显 UX 硬伤。

### 14. 管理端（Stats / Logs / Users / Roles / Storages / Sync / Settings）

- **情感反应**：整体设计良好——KPI 卡 + 表格 + 对话框 + 确认 + 分页（Logs）+ v-show 缓存（Logs）+ 动态表单（Storages）+ 权限矩阵（Roles）。
- **理性反应**：
  - `Stats`：KPI（用户数/存储后端/分享链接/操作日志）+ 服务状态 uptime + 回收站 + 磁盘占用条形图，干净。
  - `Logs`：op/login 双 tab v-show 缓存切换 + 分页 size=20 + 清空确认 + ACTION_META 图标/色调映射，良好。
  - `Users`：KPI + 过滤 + 创建/编辑 + 重置密码，**无分页**全量加载（用户多时卡）。
  - `Roles`：权限矩阵（role 列 × 权限点按模块分组）+ 每角色保存 + 防锁死说明，良好。
  - `Storages`：KPI + 类型图标 + 动态 typeFields 表单 + 测试连接 + 启用开关 + 删除，良好。
  - `Sync`：KPI + MODE_META + 创建同步对 + token 复制 + endpoint hint + 删除，良好。
  - `Settings`：**主题系统重灾区**（见下节）。
- **具体问题**：Users 无分页（P2）；Settings 主题双机制冲突（P0）。

## 三、3 个新主题重点评估（星尘 / 晨曦 / 流光）

> 对照创意设计师蓝图 `docs/2026-theme-design-blueprint.md` 评估：布局是否体现设计意图、风格是否可辨、flow 的 AI 面板是否合理、有无"为创意牺牲可用性"。

### 总判断

| 主题 | 蓝图意图 | 落地符合度 | 风格可辨 | 可用性风险 |
|---|---|---|---|---|
| 星尘 Stardust | 液态玻璃 + 深空星野 + 空间景深 | **高** | 强（深空渐变 + 悬浮玻璃岛 + 星光） | 低 |
| 晨曦 Dawn | 自然有机 + 暖色晨光 + 尊重注意力 | **高** | 强（暖白纸面 + 衬线标题 + 大留白） | 低 |
| 流光 Flow | AI 原生 + 动态渐变 + 智能中枢 | **中** | 强（紫青流光 + 暗色） | **高**（AI 面板是死胡同） |

### 星尘 Stardust（`glass.css:592-663` 变量 + `798-842` 布局）

- **符合蓝图**：深空渐变 bg（`#05070f→#121a3c`）、28px blur、悬浮玻璃岛侧栏（`border-radius:24px` + 大 shadow + `backdrop-filter blur(28px) saturate(170%)`）、双径向星云光斑 `stardust-drift` 24s/30s 漂移、文件卡片 22px 圆角 + 疏朗大间距（gap 18px）、悬停 `translateY(-4px) scale(1.02)` + 星光内发光、图标 `stardust-twinkle` 闪烁、选中态星光内发光。
- **风格可辨**：一眼是"深空 + 玻璃"，和现有毛玻璃主题有明显区别。
- **可用性**：动效克制（漂移慢、闪烁只在 hover），无"为创意牺牲可用性"。✅
- **小问题**：`scale(1.02)` 悬停偏大，密集网格下可能有轻微布局抖动（P2）。

### 晨曦 Dawn（`glass.css:668-714` 变量 + `846-903` 布局）

- **符合蓝图**：暖白纸面（`#fdf9f4→#f2e8dc`）、去玻璃去发光（`blur:0`、`backdrop-filter:none`）、Georgia/Songti 衬线标题 22px、大留白（layout padding/gap 22px、file-grid gap 22px、file-card padding 26px 18px）、动效克制（hover 仅 `translateY(-2px)`）。
- **风格可辨**：一眼是"暖色 + 纸质 + 安静"，和玻璃系主题完全两个方向。
- **可用性**：符合"尊重注意力"，密度低、不干扰。✅
- **小问题**：衬线字体栈 `Georgia, 'Songti SC', 'STSong', 'SimSun', serif`（`glass.css:884`）跨平台渲染不一致（Windows 无 Songti/STSong 会落到 SimSun 或 serif），标题观感可能不稳（P2）。

### 流光 Flow（`glass.css:719-788` 变量 + `908-924` 布局 + `939-1019` AI 面板）

- **符合蓝图**：暗色 aside（`rgba(0,0,0,0.55)`）、紫青双色流光（`--accent:#a78bfa` / `--accent-2:#22d3ee`）、双径向光斑 `flow-drift` 18s/22s、`.flow-core` 3px 流动渐变条（`background-size:220%` + `flow-core-run 5s` 循环）、侧栏底部 `.ai-panel` + 内容区 `.ai-insight`（仅 flow 显示）。
- **风格可辨**：一眼是"暗色 + 紫青流光 + AI 感"。
- **⚠️ 核心问题——AI 面板是静态死胡同（"为创意牺牲可用性"的典型）**：
  - `.ai-panel`（`App.vue:397-405`）：只有"AI 助手"标题 + 描述 + `.flow-core` 条，**无输入框、无按钮、无任何交互**。
  - `.ai-insight`（`App.vue:489-497`）：只有"AI 洞察"标题 + **"流光引擎正在为你的文件建立索引…"的永久加载文案** + `.flow-core` 条，**无真实内容、加载永不结束**。
  - 后果：flow 主题用户会看到一个"永远在索引"的假加载态 + 一个点不动的 AI 面板 → **主动误导 + 信任受损**。这是本次走查最严重的"创意压倒可用性"点位（P0）。
  - 侧栏折叠时 `.ai-panel` 隐藏（`glass.css:1017-1019`）——合理，但进一步说明 AI 面板没有实际承载内容。

## 四、体验问题清单（P0 / P1 / P2）

> P0 = 阻断核心体验 / 主动误导，必须修；P1 = 显著降级或阻断次要流程；P2 = 打磨。

### P0（必须修）

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| P0-1 | **个人用户无任何主题切换入口**，3 个新主题对终端用户完全不可达 | `App.vue:12`（setTheme 解构未用）、`:22`（showThemePicker 未用）、`useTheme.ts`（无调用点） | 大改版的 3 个新主题 = 本次改版的卖点，但个人用户根本切不到，只有管理员能设 |

## 五、具体优化建议（文件:位置 + 改法）

> 每条给"改法"，设计师/前端可直接照做。优先级对应上表。

### P0

**P0-1 · 给个人用户加主题切换入口**
- 位置：`App.vue`（header 或 user-chip 下拉）+ `useTheme.ts`。
- 改法：
  1. 在 `App.vue` header 右侧（user-chip 旁）加一个主题切换下拉，复用 `useTheme()` 的 `setTheme` + `THEMES`（9 主题）。`showThemePicker`（`:22`）已定义，直接接到模板上即可。
  2. **统一主题源**：让 `applyTheme`（Settings）和 `useTheme.apply` 写同一个 localStorage key（`nebula_theme`），且 `useTheme` 初始化时若 localStorage 为空再回退默认。这样 admin 改的主题刷新后不丢，个人用户切的也持久。
  3. 把 Settings `themeList`（13 项）与 `useTheme.THEMES`（9 项）对齐：要么把 4 个 legacy（aurora/ink/terminal/sunset）补进 THEMES，要么从 themeList 移除，避免两套清单。

**P0-2 · 修双主题机制冲突**
- 位置：`Settings.vue:209-211`（applyTheme）+ `useTheme.ts:32-45`。
- 改法：见 P0-1 第 2 点——单一数据源（localStorage `nebula_theme`），admin 与个人用户共用，刷新不丢。admin 的 `applyTheme` 改为调用 `useTheme.setTheme`（或写同一 key 后再 setAttribute）。

**P0-3 · flow 的 AI 面板二选一**
- 位置：`App.vue:397-405`（ai-panel）、`:489-497`（ai-insight）。
- 改法（二选一）：
  - **A（推荐，低成本）**：降级为"装饰 + 诚实文案"。把"正在建立索引…"改成静态说明（如"流光主题 · AI 能力规划中"），去掉永久加载态；`.ai-panel` 保留视觉但去掉"助手"暗示（或加一个"敬请期待"）。**不要假装在工作**。
  - **B（高成本，真做）**：接真实能力——`ai-insight` 展示真实文件统计/最近变更/可搜索入口，`ai-panel` 加一个输入框做文件检索。若近期无 AI 后端，选 A。

**P0-4 · Media 视频预览改流式**
- 位置：`Media.vue:78-83`。
- 改法：
  1. 视频用 `<video src>` 指向带鉴权的流式端点（Range 请求），支持 seek，而非 `res.blob()` 整文件下载。
  2. 列表加视频缩略图（后端生成或前端 `video` 抓帧），替换 42px 图标。
  3. 若短期无法流式，至少加"大文件提示 + 进度条"，不要静默整文件下载。

## 六、给两位设计师的分工建议

- **创意设计师**：重点看 P0-3（flow AI 面板的"创意 vs 可用性"取舍）、P2-6/P2-7（动效与字体的克制度）。星尘/晨曦两个主题落地质量高，可保留；流光主题的"AI 中枢"概念好，但当前是空壳，需要产品决策"真做还是降级"。
- **UI 设计师**：重点看 P0-1/P0-2（主题入口 + 双机制统一，这是本次改版能否被用户感知到的前提）、P1-1~P1-5（登录/转存/快捷访问/隐藏空间/文件工具栏的功能完整性）。

## 七、一句话总结

**功能面完成度高、管理端设计好；但本次改版的 3 个新主题里，星尘/晨曦立住了，流光是空壳（假 AI）；更大的问题是——个人用户根本切不到任何主题（无入口 + 双机制冲突），等于新主题对目标用户不可见。** 先修"主题可达性"（P0-1/P0-2）+ "flow 假 AI"（P0-3）+ "视频流式预览"（P0-4），再修 P1 的功能死胡同，改版才能真正落到用户手里。
